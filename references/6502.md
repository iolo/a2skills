# 6502 and ca65 Cheat Sheet

## Use This For

Use when writing or debugging Apple II 6502 assembly, especially in `ca65`.
Prefer `ca65` syntax and Apple II-relevant examples.

## Default Rules

- Use labels, not hard-coded branch offsets.
- Prefer zero page for hot paths.
- State machine assumptions when using ROM calls, soft switches, or slot behavior.
- Comment non-obvious hardware access.
- Prefer `cl65 -t apple2` for simple builds.

## Core Patterns

### Load immediate

```asm
lda #$10
```

### Store to memory

```asm
lda VALUE
sta $300
```

### Counted loop

```asm
ldx #10
loop:
    dex
    bne loop
```

### Compare and branch

```asm
cmp #$20
beq done
```

### Call ROM routine

```asm
COUT = $FDED

lda #'A'
jsr COUT
```

## Addressing Mode Reminders

- `#$10` immediate value
- `$20` zero page
- `$2000` absolute
- `$20,X` indexed zero page
- `$2000,X` indexed absolute
- `($20),Y` indirect indexed

Use zero page when practical.
Watch for page crossing with indexed modes.

## Flag Rules That Matter

- `CMP` sets flags only.
- `ADC` and `SBC` depend on carry.
- `BEQ` / `BNE` depend on zero flag.
- `BCC` / `BCS` depend on carry.
- `BMI` / `BPL` depend on negative.
- `BIT` is useful for testing status-style values.

## Common Gotchas

- forgetting `CLC` before `ADC`
- wrong branch for the intended flag
- wrong addressing mode
- clobbering `A`, `X`, or `Y`
- stack imbalance with `JSR` / `RTS`
- assuming one Apple II ROM behavior applies to all models

## Apple II Notes

- Name ROM entry points explicitly.
- Name soft switches explicitly.
- State whether code assumes Apple II, Apple II+, Apple IIe, or enhanced IIe.
- Be cautious with firmware, keyboard, video, and slot-dependent behavior.

## Debug Checklist

Check:

- carry handling
- branch condition correctness
- register preservation
- addressing mode choice
- page crossing where relevant
- machine-specific ROM or hardware assumptions
